# v3.3 支付与安全护栏矩阵

更新时间：2026-06-02

## 结论

`v3.3` 第一批只做支付、安全和升级阻塞面的盘点，不修改支付实现、不新增 SDK、不恢复退役通道、不进入 Laravel 大版本升级实验。

当前执行边界：

- 保留支付通道：官方支付宝、官方微信、易支付、Epusdt
- 退役支付通道：PayPal、Stripe、Coinbase、Mapay、TokenPay、PayJS、Vpay、Paysapi 等继续保持不可恢复
- 安全面：后台批量动作、支付配置、上传、模板输入、邮件发送、通知配置、安装默认值继续按状态矩阵维护
- 升级面：Laravel 8.83 stable 维持主线，Dcat 最小兼容层、`swiftmailer/swiftmailer`、`symfony/debug` 和保留支付依赖继续作为后续清障项

## 支付回调异常路径矩阵

| 异常路径 | 当前状态 | 主要护栏 | 后续动作 |
| --- | --- | --- | --- |
| 签名失败 | 已处理 | `PaymentCallbackServiceTest` 和保留通道通知测试覆盖异常不触发履约 | 后续改回调必须同步维护测试 |
| 重复通知 | 已处理 | 保留通道通知服务和控制器测试覆盖幂等推进 | 继续维护，不新增业务语义 |
| 金额不一致 | 已处理 | `PaymentCallbackServiceTest` 覆盖金额不一致时不完成订单、不写交易号、不增加销量 | 继续维护 |
| 订单不存在 | 已处理 | 公共回调服务和通道控制器测试覆盖错误返回 | 继续维护 |
| 支付方式不匹配 | 已处理 | 支付入口与通道回调测试覆盖上下文不一致场景 | 继续维护 |
| 已完成订单重复通知 | 已处理 | 保留通道异常路径测试覆盖已完成订单不重复推进 | 继续维护 |

本批不修改 `pay-gateway/{handle}/{payway}/{orderSN}`、回调 URL、订单完成语义或履约链路。

## 下一批建议

`v3.3` 第二批建议只从本矩阵中选择测试缺口或护栏缺口执行：

1. 补上传、模板输入、邮件发送和通知配置的安全输入面测试。
2. 复核退役通道关键字是否只出现在历史日志、退役说明、防回流测试和本矩阵。
3. 复核保留通道回调异常测试是否覆盖最新控制器路径。
4. 不进入支付 SDK 扩展，不恢复退役通道，不修改公开接口。
