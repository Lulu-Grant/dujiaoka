# 支付网关整改清单

更新时间：2026-05-31

本文档用于追踪当前仓库内支付网关的维护范围和退役边界。

## 当前维护通道

| 网关 | 路由 | 当前状态 | 备注 |
| --- | --- | --- | --- |
| 官方支付宝 | `/pay/alipay` | 保留维护 | 继续通过 `AlipayNotificationService` 约束回调安全 |
| 官方微信 | `/pay/wepay` | 保留维护 | 继续通过 `WepayNotificationService` 约束回调安全 |
| 易支付 | `/pay/yipay` | 保留维护 | 复用 `PaymentCallbackService` 统一通知骨架 |
| Epusdt | `/pay/epusdt` | 保留维护 | 复用 `PaymentCallbackService` 统一通知骨架，作为当前 USDT 通道 |

## 已退役通道

以下通道不纳入新版本维护范围，不再进入路由、控制器、服务、依赖锁文件或支付样例种子。

| 网关 | 状态 | 说明 |
| --- | --- | --- |
| PayPal | 已退役 | 已移除控制器、服务、SDK 依赖和测试基线 |
| Stripe | 已退役 | 已移除控制器、服务、SDK 依赖、收银页资源和测试基线 |
| Coinbase | 已退役 | 已移除 webhook 控制器、服务和测试基线 |
| Mapay | 已退役 | 已移除路由、控制器和样例种子 |
| TokenPay | 已退役 | 已移除路由、控制器、样例种子和各币种变体 |
| Paysapi | 已退役 | 已从路由、控制器和测试基线移除 |
| Vpay | 已退役 | 已从路由、控制器和测试基线移除 |
| PayJS | 已退役 | 已从路由、控制器、依赖锁文件和支付样例种子移除 |

## 当前约束

- 后续不新增公开前台支付 API。
- 后续不修改保留通道的回调 URL 语义。
- 退役通道不得作为 beta.2、RC 或 stable-ready 的维护目标恢复。
- 支付样例种子只保留官方支付宝、官方微信、易支付和 Epusdt。
- 后台支付通道管理页仍可展示历史数据的生命周期状态，但不得重新灌入退役样例。

## 下一步默认动作

1. 继续补保留通道的异常路径测试：重复通知、签名失败、金额不一致、已完成订单重复推进、异常路径不触发履约。
2. 复查保留通道的配置输入面，避免批量动作触碰密钥、商户号和支付路由。
3. 在 release 文档中持续标明退役通道范围，避免后续回流。

## beta.1 支付安全验收口径

- 支付完成入口重复通知不重复履约、不重复加销量、不重复派发副作用。
- 金额不一致、签名失败或网关异常时，订单不得从待支付推进到完成。
- 已完成订单收到重复回调时必须保持当前状态，并留下可测试的幂等行为。
- 已退役通道不重新进入路由、样例种子、依赖锁文件或后台新增功能。
